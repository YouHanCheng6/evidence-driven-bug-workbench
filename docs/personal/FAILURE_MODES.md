# 失败模式、恢复与幂等

| 失败点 | 行为 | 不允许的行为 |
| --- | --- | --- |
| 附件无法解析 | 保留工单文本和明确缺口，必要时终止 | 猜测截图或视频内容 |
| 平台结果为空 | 使用模块做仓库回退，但不虚构复现端 | 用关键词强行覆盖语义结果 |
| 日志/私有规则不可用 | 以空的可选上下文继续 | 把工具不可用解释成业务结论 |
| Tabby 不可用或无命中 | 向 Codex 提供空候选，允许其只读搜索 | 把搜索服务就绪当成证据 |
| 候选与 checkout 不一致 | 丢弃候选并记录原因 | 引用索引中的过期片段 |
| Codex 认证/运行时缺失 | 在调查前失败，保留已准备事实 | 回退到未声明的模型或旧引擎 |
| Codex 超时/空响应 | 保存错误和已有状态，允许显式重试 | 伪造报告或悄悄启动第二套流程 |
| 报告格式不合格 | 同一会话最多一次受约束修正 | 新开总结会话丢失证据来源 |
| 备注提交失败 | 保持未确认状态，交由恢复逻辑判断 | 在结果不明时盲目重复 POST |
| 页面读回滞后 | 页面优先，必要时查询历史接口 | 因切换确认渠道再次提交 |
| 批次中单条失败 | 记录该项并继续/恢复其余项 | 改写冻结的 ID 顺序或重复已完成项 |

## 单次写入原则

写回前先从完整报告确定性提取第三、四节，再在传输边界做 HTML 转义。POST 只发生一次；提交后的页面和历史接口都是确认渠道，不是第二次写入入口。即使读回暂时不可见，也必须先分辨“提交失败”和“提交成功但读取滞后”。

## 恢复边界

持久状态记录已完成阶段，使进程重启后可以从安全边界继续。已经确认的备注不会在恢复时重写；批次保存当前索引和每项结果。新工作流的终态是 `note_written`，不存在自动源码修复、测试、提交或工单状态变更，因此这些动作也不属于恢复范围。

## 历史兼容

旧记录可能含真实 diff、验收和回滚信息。系统保留只读展示及回滚能力，但不会把历史字段解释为当前引擎仍可启动。公开副本中的相关兼容代码应与新任务可达路径分开阅读。
