# 脱敏边界与限制

## 已包含

- 当前工作树中与个人定制有关的源码/配置/品牌中性资源文件副本，逐文件清单和哈希见 `PERSONAL_EXPORT_MANIFEST.json`；
- 缺陷工作流状态机、Tabby 检索、当前 checkout 验证、只读 Codex 调查、四段报告、修改建议和工单写回代码；
- 日志索引、只读日志专家选择原始来源/行号及后端恢复完整脱敏记录的实现；
- 备注确认后的可选第四节修改执行、逐项结果和前后快照回退/恢复代码；
- 主助手的精确选择、持久化串行批次与取消适配；
- 单文件限量 Git 历史核验和可选日报看板投影；
- 前端工作台和源码证据组件；
- 虚构的小型票据、源码与证据包；
- 上游 MIT 许可证、归属说明和独立发布防护。

清单收录完整文件副本，其中含上游原代码，不能把总行数当作作者新增行数。

2026-10-22 增量保留了按来源优先级的检索融合、日志专家与原始记录交付、受限修改执行及可逆快照设计。产品配置只约束源码范围，不凭配置制造候选。可选远端知识接口统一使用 `examplewiki`、`ExampleWikiMcp`、`DEERFLOW_BUG_EXAMPLE_WIKI_AUTHORIZATION` 和八个 `example_*` 工具名；这些是示例协议，实际连接需要适配。知识内容、服务端实现、真实接口映射及连接 JSON 均未导出。目录和页面覆盖字段也使用虚构名称。

按作者要求，公开版移除了旧视觉模型函数、常量及专用导入，仅保留 Codex 视觉提取。这是明确记录的展示版差异，外层实际运行代码不受影响。框架上游的其他模型提供商示例仍保留，它们不属于 Bug 附件识别链。

公开示例默认关闭 `bug_analysis.repair.enabled`，保留执行器作为工程设计展示。部署方若启用，必须自行配置有权限的仓库与模型，并理解它会写入选定源码；只读调查的沙箱并不覆盖此后独立的修改阶段。模型名、网关环境变量名和示例接口不是凭据，也不代表任何可直接连接的私人服务。

## 明确排除

- 任何公司源码仓库、Tabby 私有复合索引及其片段；
- 真实工单、附件、日志、索引、查询轨迹、修改前后快照、数据库和运行产物；
- 真实业务知识文件、产品映射和内部检索策略数据；
- 私有 Agent 的 `SOUL.md`、用户记忆与个人运行配置；
- API Key、令牌、Cookie、认证文件、私有域名和本机绝对路径；
- 企业测试夹具、真实回归样例和内部设计文档；
- 独立铁路、考试学习和微信小程序项目；
- 外层 DeerFlow 的 Git 历史、上游 CI 工作流和内部交付包；`my/.git` 只是这个公开副本自身的独立发布历史。

仓库、产品、人员、包名、模型名和服务地址均替换为 `sample_*`、`Bug Workbench`、`example.invalid` 等示例值。公开目录不保存原值到占位符的映射。

## 不能从本副本推断的内容

公开代码展示接口和工程设计，不证明它能连接任何实际工单、日志、Tabby、Codex 运行时或源码库。私有业务规则缺失时，一些软排序不会生效；企业测试被排除，因此不能据此声称生产兼容性或修复准确率。

本次公开副本整理没有运行真实调查、外部模型调用、工单备注写回、对接企业仓库的修改执行或端到端部署。离线测试只验证发布边界、哈希、语法与虚构契约/案例，不证明实际外部服务兼容性、执行准确性或恢复能力已经在生产验证。

## 后续发布纪律

只在 `my` 内建立独立 Git 仓库。每次增加文件都应重新运行发布检查、独立密钥扫描并人工阅读 diff；不要复制真实日志来“增强演示”，也不要把外层仓库的 `.git`、配置或 Agent 目录带入。自动扫描是辅助措施，不能代替人工判断商业机密。
