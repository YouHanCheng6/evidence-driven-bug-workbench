# 脱敏边界与限制

## 已包含

- 当前工作树中与个人定制有关的 106 个新增或修改源码/配置/品牌中性资源文件副本；
- 缺陷工作流状态机、Tabby 检索、当前 checkout 验证、只读 Codex 调查、四段报告、修改建议和工单写回代码；
- 主助手的精确选择与串行批次适配；
- 前端工作台和源码证据组件；
- 虚构的小型票据、源码与证据包；
- 上游 MIT 许可证、归属说明和独立发布防护。

清单中的约 5.5 万行是完整文件总行数，其中含上游原代码，不能当作作者新增行数。

## 明确排除

- 任何公司源码仓库、Tabby 私有复合索引及其片段；
- 真实工单、附件、日志、追踪、数据库和运行产物；
- 真实业务知识文件、产品映射和内部检索策略数据；
- 私有 Agent 的 `SOUL.md`、用户记忆与个人运行配置；
- API Key、令牌、Cookie、认证文件、私有域名和本机绝对路径；
- 企业测试夹具、真实回归样例和内部设计文档；
- 外层 Git 历史、上游 CI 工作流和内部交付包。

仓库、产品、人员、包名、模型名和服务地址均替换为 `sample_*`、`Bug Workbench`、`example.invalid` 等示例值。公开目录不保存原值到占位符的映射。

## 不能从本副本推断的内容

公开代码展示接口和工程设计，不证明它能连接任何实际工单、日志、Tabby、Codex 运行时或源码库。私有业务规则缺失时，一些软排序不会生效；企业测试被排除，因此不能据此声称生产兼容性或修复准确率。

本次没有运行真实调查、外部模型调用、备注写回、源码修改或端到端部署。离线测试只验证发布边界、哈希、语法与虚构案例。

## 后续发布纪律

只在 `my` 内建立独立 Git 仓库。每次增加文件都应重新运行发布检查、独立密钥扫描并人工阅读 diff；不要复制真实日志来“增强演示”，也不要把外层仓库的 `.git`、配置或 Agent 目录带入。自动扫描是辅助措施，不能代替人工判断商业机密。
